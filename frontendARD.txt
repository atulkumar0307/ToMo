1. Overview
Tomo is a social activity app where users:

Create and join real-world activities (runs, coffee meetups, hikes, etc.)
Manage participants (approve/reject join requests)
Post Highlights (media posts) after an activity ends
The Flutter app consumes a REST API. This doc covers everything the backend must implement.

2. Authentication
Field	Detail
Auth type	JWT Bearer Token
Access token header	Authorization: Bearer <accessToken>
Token refresh endpoint	POST /auth/refresh-token
Body for refresh	{ "refreshToken": "..." }
On 401 response	Flutter auto-retries with refreshed token
Note: All Activity and Highlight endpoints require authentication. Return 401 if token is missing or expired.

4. Activity Status Lifecycle

┌──────────────┐
                   │   UPCOMING   │  ← default on create (startTime in future)
                   └──────┬───────┘
                           │ (startTime reached OR host calls /start)
                           ▼
                   ┌──────────────┐
                   │   ONGOING    │
                   └──────┬───────┘
                           │ (endTime reached OR host calls /complete)
                           ▼
                   ┌──────────────┐
            ┌─────▶│  COMPLETED   │◀─────── host calls POST /activities/:id/complete
            │      └──────────────┘
            │
            │      ┌──────────────┐
            └─────▶│  CANCELLED   │◀─────── host calls POST /activities/:id/cancel
                   └──────────────┘
                   
                   ┌──────────────┐
                   │   EXPIRED    │◀─────── auto: endTime passed, never completed
                   └──────────────┘
                   
                   ┌──────────────┐
                   │   DELETED    │◀─────── host calls DELETE /activities/:id
                   └──────────────┘
Rules:
UPCOMING → ONGOING → COMPLETED (happy path)
UPCOMING or ONGOING → CANCELLED (host action)
UPCOMING or ONGOING → DELETED (host action — soft delete)
If endTime passes without explicit /complete, mark as EXPIRED automatically (via cron/scheduler)
Highlights can only be created for COMPLETED, CANCELLED, EXPIRED activities (not UPCOMING or ONGOING)
What Flutter shows:
Status	Section	Badge Color
UPCOMING	Active	Blue
ONGOING	Active	Green pulse
COMPLETED	Past	Green
CANCELLED	Past	Red
EXPIRED	Past	Amber/Orange
DELETED	Past	Red
5. Activity APIs
5.1 List Discovery Activities

GET /activities?page=1&limit=50&category=SPORTS&size=small
Query params:

page — integer (default 1)
limit — integer (default 50, max 100)
category — optional enum string (see §10)
size — small | medium | large | all (based on maxParticipants)
Response: { success: true, data: [...Activity], pagination: {...} }

5.2 List My Activities (Combined)

GET /activities/mine?page=1&limit=50
Returns both hosted and joined activities merged. Flutter splits them client-side into Active / Past based on status.

Alternative already used in Flutter:


GET /activities/mine/hosted
GET /activities/mine/joined
5.3 Get Single Activity

GET /activities/:id
Returns full activity with host, userParticipationStatus, and highlightCount (number of highlights posted).

5.4 Create Activity

POST /activities
Body:

json

{
  "title": "Morning Run at Marine Drive",
  "description": "Early morning run along the promenade...",
  "category": "SPORTS",
  "emoji": "🏃",
  "locationName": "Marine Drive, Mumbai",
  "address": "Marine Drive, Nariman Point, Mumbai 400021",
  "city": "Mumbai",
  "latitude": 18.9432,
  "longitude": 72.8231,
  "startTime": "2026-06-15T06:00:00.000Z",
  "endTime": "2026-06-15T08:00:00.000Z",
  "maxParticipants": 15
}
Validations:

title — max 100 chars, required
description — max 1000 chars, required
category — must be a valid enum value
startTime must be in the future
endTime must be after startTime
maxParticipants — min 2, max 500
Response: { success: true, data: Activity }

5.5 Update Activity

PATCH /activities/:id
Same body as create. Only host can update. Cannot update if status is COMPLETED, CANCELLED, DELETED, or EXPIRED.

5.6 Delete Activity

DELETE /activities/:id
Soft delete — set status = DELETED. Only host can delete.

5.7 Start Activity (Manual)

POST /activities/:id/start
Changes status from UPCOMING → ONGOING. Only host. (Optional — status can auto-transition by time too.)

5.8 Complete Activity

POST /activities/:id/complete
Changes status from ONGOING → COMPLETED. Only host.

5.9 Cancel Activity

POST /activities/:id/cancel
Changes status to CANCELLED. Only host. Can cancel from UPCOMING or ONGOING.

6. Participant APIs
6.1 Join Activity

POST /activities/:id/join
Logged-in user requests to join. Sets status = PENDING. Returns error if:

Already joined
Activity is full (approvedCount >= maxParticipants)
Activity is not UPCOMING or ONGOING
User is the host
6.2 Withdraw from Activity

POST /activities/:id/withdraw
Removes participant record. Can only withdraw if status is PENDING or APPROVED and activity hasn't ended.

6.3 List Participants

GET /activities/:id/participants
Returns all participants with their status. Only host can see full list with PENDING entries.

Response:

json

{
  "success": true,
  "data": {
    "approved": [...Participant],
    "pending": [...Participant],
    "rejected": [...Participant]
  }
}
6.4 Approve Participant

POST /activities/:id/participants/:userId/approve
Only host. Changes participant status to APPROVED. Increment approvedCount.

6.5 Reject Participant

POST /activities/:id/participants/:userId/reject
Only host. Changes participant status to REJECTED.

7. Highlight APIs ⭐ NEW
A Highlight is a post containing photos and/or videos from a completed activity.
Created via multipart/form-data because it includes binary media files.

7.1 Create Highlight

POST /activities/:activityId/highlights
Content-Type: multipart/form-data
Who can post: Only users whose participation status is APPROVED, OR the host of the activity.

Form fields:

Field	Type	Required	Notes
title	string	✅ Yes	Max 150 chars
caption	string	No	Max 300 chars
description	string	No	Max 1000 chars
tags	string (JSON array)	No	e.g. '["vibes","morning_run"]'
mediaOrder	string (JSON array)	No	Order of files e.g. '[0,2,1]'
media	file[]	✅ Yes	Field name: media, accept multiple
Media file validations:

Total files: min 1, max 7
Images: JPEG, PNG, WEBP — no size limit recommended (compress server-side to max 5 MB)
Videos: MP4, MOV, WEBM — max duration: 40 seconds (validate server-side)
Combined total: max 7 items (images + videos together)
Example multipart request (pseudocode):


POST /activities/act_001/highlights
Authorization: Bearer <token>
Content-Type: multipart/form-data
title=Marine Drive Run Highlights ✨
caption=Nothing beats a sunrise run by the sea 🌅
description=Caught 4 amazing moments...
tags=["morning_run","marine_drive","fitness"]
media=<file1.jpg>
media=<file2.jpg>
media=<clip.mp4>

7.3 Get Single Highlight

GET /highlights/:highlightId
7.4 Update Highlight (Author only)

PATCH /highlights/:highlightId
Content-Type: application/json
Body (only metadata, no new media):

json

{
  "title": "Updated title",
  "caption": "New caption",

DELETE /highlights/:highlightId
Soft delete — set status = DELETED. Author can delete their own. Host can delete any highlight on their activity.

7.6 List My Highlights (All activities)

GET /highlights/mine?page=1&limit=20
Returns all highlights created by the logged-in user across all activities.

8. Business Rules & Validations
Activity Rules
Rule	Detail
Who can create	Any authenticated user
Who can update/delete/cancel	Only the host
Max title length	100 chars
Max description length	1000 chars
Min participants	2
Max participants	500
Start time	Must be in the future at creation
End time	Must be after start time
Min duration	15 minutes
Max advance booking	90 days from today
Can edit after COMPLETED/CANCELLED	❌ No
Participant Rules
Rule	Detail
Can host join own activity	❌ No
Can join after activity ends	❌ No (status must be UPCOMING or ONGOING)
Can join if full	❌ No (approvedCount >= maxParticipants)
Join creates	Participant record with status = PENDING
Withdraw	Removes participant. Decrements count if was APPROVED.
Double join prevention	Return 409 if already in participants table
Highlight Rules
Rule	Detail
Who can post	Only host OR approved participant
When can post	Only if activity is COMPLETED, CANCELLED, or EXPIRED
Min media	1 item
Max media (combined)	7 items
Image formats	JPEG, PNG, WEBP
Video formats	MP4, MOV, WEBM
Max video duration	40 seconds (reject if longer)
Title required	✅ Yes
Caption	Optional (max 300 chars)
Description	Optional (max 1000 chars)
Tags	Optional, max 20 tags, each max 50 chars
Tag format	Lowercase, underscores for spaces (morning_run)
One user can post multiple highlights per activity	✅ Yes (no limit)
Who can delete	Author only, or activity host
Media order	Preserved — order field in DB
9. DB Relationships

User
 ├── hosts many Activities        (Activity.hostId → User.id)
 ├── joins many Activities        (via Participant table)
 └── creates many Highlights      (Highlight.userId → User.id)
Activity
 ├── belongs to one User (host)   (Activity.hostId → User.id)
 ├── has many Participants         (Participant.activityId → Activity.id)
 └── has many Highlights          (Highlight.activityId → Activity.id)
Participant
 ├── belongs to one User          (Participant.userId → User.id)
 └── belongs to one Activity      (Participant.activityId → Activity.id)
 UNIQUE constraint: (userId, activityId)
Highlight
 ├── belongs to one Activity      (Highlight.activityId → Activity.id)
 ├── belongs to one User (author) (Highlight.userId → User.id)
 └── has many HighlightMediaItems (HighlightMediaItem.highlightId → Highlight.id)
HighlightMediaItem
 └── belongs to one Highlight     (HighlightMediaItem.highlightId → Highlight.id)
Suggested DB Schema (SQL-style pseudocode)
sql

-- activities table
CREATE TABLE activities (
  id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  host_id          UUID NOT NULL REFERENCES users(id),
  title            VARCHAR(100) NOT NULL,
  description      TEXT,
  category         VARCHAR(20) NOT NULL,
  emoji            VARCHAR(10),
  location_name    VARCHAR(200),
  address          TEXT,
  city             VARCHAR(100),
  latitude         DECIMAL(9,6),
  longitude        DECIMAL(9,6),
  start_time       TIMESTAMPTZ NOT NULL,
  end_time         TIMESTAMPTZ NOT NULL,
  max_participants INTEGER NOT NULL DEFAULT 10,
  approved_count   INTEGER NOT NULL DEFAULT 0,
  pending_count    INTEGER NOT NULL DEFAULT 0,
  status           VARCHAR(20) NOT NULL DEFAULT 'UPCOMING',
  created_at       TIMESTAMPTZ DEFAULT now(),
  updated_at       TIMESTAMPTZ DEFAULT now()
);
-- participants table
CREATE TABLE participants (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  activity_id  UUID NOT NULL REFERENCES activities(id) ON DELETE CASCADE,
  user_id      UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  status       VARCHAR(20) NOT NULL DEFAULT 'PENDING',
  joined_at    TIMESTAMPTZ DEFAULT now(),
  approved_at  TIMESTAMPTZ,
  UNIQUE(activity_id, user_id)
);
-- highlights table
CREATE TABLE highlights (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  activity_id UUID NOT NULL REFERENCES activities(id) ON DELETE CASCADE,
  user_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title       VARCHAR(150) NOT NULL,
  caption     VARCHAR(300),
  description TEXT,
  tags        TEXT[],                -- array of tag strings
  status      VARCHAR(20) NOT NULL DEFAULT 'PUBLISHED',
  created_at  TIMESTAMPTZ DEFAULT now(),
  updated_at  TIMESTAMPTZ DEFAULT now()
);
-- highlight_media_items table
CREATE TABLE highlight_media_items (
  id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  highlight_id     UUID NOT NULL REFERENCES highlights(id) ON DELETE CASCADE,
  type             VARCHAR(10) NOT NULL,   -- 'IMAGE' or 'VIDEO'
  url              TEXT NOT NULL,          -- CDN URL
  thumbnail_url    TEXT,                   -- for video thumbnails
  order_index      INTEGER NOT NULL,       -- display order
  duration_seconds INTEGER,               -- for videos only
  file_size_bytes  BIGINT,
  mime_type        VARCHAR(50),
  created_at       TIMESTAMPTZ DEFAULT now()
);

12. Error Codes
HTTP	Code	When
400	VALIDATION_ERROR	Missing/invalid fields
400	INVALID_CATEGORY	Unknown category value
400	INVALID_TIME	startTime in past, or endTime before startTime
400	VIDEO_TOO_LONG	Video > 40 seconds
400	TOO_MANY_MEDIA	More than 7 media items
401	UNAUTHORIZED	No token or expired token
403	FORBIDDEN	Authenticated but not allowed (not host, not participant, etc.)
403	NOT_PARTICIPANT	User not approved participant, trying to post highlight
403	ACTIVITY_NOT_PAST	Trying to post highlight on UPCOMING/ONGOING activity
404	ACTIVITY_NOT_FOUND	Activity ID does not exist
404	HIGHLIGHT_NOT_FOUND	Highlight ID does not exist
409	ALREADY_JOINED	User already has a participant record
409	ACTIVITY_FULL	approvedCount >= maxParticipants
422	CANNOT_JOIN_OWN	Host trying to join their own activity
500	INTERNAL_ERROR	Unexpected server error
13. Media Upload Notes (for CDN/Storage)
Use cloud storage (AWS S3 / GCP Storage / Cloudinary)
For videos: generate a thumbnail server-side after upload (first frame, 1 second in), store the URL in thumbnail_url
Image compression: resize to max 1920px on longest edge, convert to WebP for storage efficiency
Video transcoding: transcode to H.264 MP4 for compatibility
Return CDN URLs (not presigned S3 URLs) in all responses so Flutter can display them without tokens
14. Flutter Integration Notes (for Backend Dev)
These are the exact calls Flutter is making. Make sure responses match this shape:

dart

// Get my activities (called on Activity tab load)
GET /activities/mine/hosted
GET /activities/mine/joined
// Create Highlight (multipart from HighlightConfirmScreen)
POST /activities/:activityId/highlights
// Fields: title, caption, description, tags (JSON string), media (files[])
// After success, pop back to Activity tab
// Flutter does: Navigator.popUntil(route.isFirst || route.name == '/activity')
Flutter splits activities into Active/Past client-side:

Active → status is UPCOMING or ONGOING
Past → status is COMPLETED, CANCELLED, EXPIRED, or DELETED
"Add Highlight" button is shown only for Past activities where the current user was a participant or host.
